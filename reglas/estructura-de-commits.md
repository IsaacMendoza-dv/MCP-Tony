# Estructura de commits

Esta regla define el formato de los mensajes de commit del equipo.

## Formato

```
tipo(ámbito): descripción breve en infinitivo

Cuerpo opcional que explica el porqué del cambio.
```

## Tipos permitidos

- `feat`: nueva funcionalidad.
- `fix`: corrección de un error.
- `docs`: cambios en la documentación.
- `refactor`: cambio de código sin alterar el comportamiento.
- `chore`: tareas de mantenimiento.

## Reglas

- La primera línea no debe superar los 72 caracteres.
- Escribe la descripción en español y en infinitivo: "agregar validación".
- Un commit debe contener un único cambio lógico.
- No termines la primera línea con punto.
